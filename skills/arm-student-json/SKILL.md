# Вход
Пользователь присылает текст задания (введение, постановка, алгоритм, входные/выходные данные) и JSON-шаблон. Если чего-то нет, попроси.

# Выход
1. Один валидный JSON, отформатированный с отступами (2 пробела), в одном блоке ```json.
2. После него таблица тестов (см. «Тесты»). Если пользователь просит только JSON, тесты не выводить.
Другие пояснения только если есть допущения (одной-двумя строками).

# Что копировать из шаблона дословно
version, mxGraphScheme (пустая строка), task_text (без изменений, с исходными class/style), code.version и code.folders. Не упрощать HTML.

# Порядок работы
1. Определи тип: процедурное (функции) или ООП (классы).
2. Выпиши сущности: объекты, функции, классы, поля, методы, конструкции.
3. Напиши код (см. «Код»), по нему строй алгоритм: один шаг алгоритма = одно действие кода, тот же порядок.
4. Заполни method2, algo2, code.files.
5. Проверь по чек-листу. Посчитай тесты по коду вручную.

# method2
- main.objects: cin (если есть ввод) и cout (если есть вывод), type "iostream", desc «ввод информации» / «вывод информации». Для ООП добавь объекты классов: name = имя объекта, type = имя класса, desc = назначение. Только реально используемые.
- main.functions: свободные функции кроме main, имена как в algo2 и в коде. В ООП методы сюда не писать. Без дублей имён.
- main.custom: только реально встречающиеся конструкции: "if else - условный оператор", "for - оператор цикла со счетчиком", "while - оператор цикла с предусловием", "do while - оператор цикла с постусловием", для динамики "new - оператор динамического создания объекта", "delete - оператор уничтожения динамически созданного объекта". Нет конструкций: пустой массив [].
- classes (ООП, обязательно заполнять; пустой массив только если классов нет):
  {name, desc, bases:[{id,is_virtual:false,name:"",mod:"public"}] (без наследования), fields:[{id,semantics,name,type,mod}], methods:[{id,semantics,name}]}.
  Конструкторы и деструктор тоже методы (name "A", "~A"). Отличия между классами отражай в semantics. Для struct mod по умолчанию public, для class private.

# algo2
- Порядок: main первым, затем функции и методы в порядке упоминания в задании.
- main: kind "0", class "", access "", params "", ret «целое - индикатор корректности завершения программы».
- Свободная функция: kind "0", access "public". Метод класса: kind "1", class = имя класса, access = реальный модификатор метода (не копировать "private" из эталона).
- params: «тип имя - описание» через запятую; типы словами: целое, вещественное, строка, вещественный массив mass + отдельное целое n. Конструктор/деструктор: ret «нет - …».
- Строки алгоритма: {id, no, predicate, actions, next, comment}. id с 0 без пропусков, no с 1 без пропусков. next строкой, последний шаг ведёт в "0".
- Шаг с условием = две строки с одним no. 1-я: predicate, действия при истине, next, и "__rowspan":{"no":2}. 2-я: predicate "", действия при лжи («переход к следующему шагу», если нет), next. __rowspan только у первой строки.
- Цикл со счётчиком: A инициализация, next=B. B условие: истина = тело + i++, next=B (на шаг-условие); ложь = выход. Тело из нескольких действий разнеси на шаги, последний делает i++ и ведёт на B.
- Один шаг — одно простое действие. Объявление до использования, ввод после объявления, инициализация до цикла.
- Экранирование в predicate/actions: < → &lt;, > → &gt;, " → &quot;, & → &amp;, перенос → <br/>.
- Имена переменных, функций, классов, регистр — везде одинаковые и совпадают с кодом. Строки вывода точно как в «Выходных данных» (регистр, пробелы, двоеточия, без кавычек-подстановок). Не добавлять шагов, которых нет в задании. Если шаги задания порядково отличаются от естественного кода, следовать коду и тому, что допускает задание.

# Код (code.files)
Поле code.files заполняется всегда (не оставлять заглушку шаблона, не оставлять пустым).
- Отступы только табуляцией (в JSON \t), никаких 4 пробелов. Комментариев нет. Каждый файл заканчивается \n.
- ООП: на каждый класс пара <класс>.h (folder 0, "Header Files") и <класс>.cpp (folder 1, "Source Files"); main.cpp (folder 1). Если задание явно требует один файл, следовать заданию.
- .h: #ifndef NAME_H / #define NAME_H / #endif; только объявления. Если нужен string, #include <string> и std::string. .cpp: #include "класс.h", методы через Класс::метод.
- Модификаторы доступа и ключевые слова строго по заданию (например, в struct не писать public, в class не писать private; класс: поле без модификатора первым, struct: private в конце).
- Геттеры const, если это не противоречит заданию. В main всегда return 0.
- Процедурные задания: один main.cpp; запреты задания (new/delete, сторонние библиотеки, второй массив) соблюдать. Не использовать VLA и расширения, если задание требует безопасного массива: фиксированный размер по максимуму из условия.
- Формат записи элемента: {"name","folder","folder_name","content"}; в content экранировать \n, \t, \".
- Консольный ввод/вывод через iostream; используемые using/std:: единообразно по всем файлам.

# Тесты
Таблица: № | вход | ожидаемый вывод | что проверяет. Минимум 3: минимальный/типовой, граничный, отрицательные/ноль (если применимо); для условных веток по тесту на каждую ветку. Ожидаемый вывод считать вручную по коду и по формату из задания. Если пример в задании противоречит формуле, сообщить об этом, не подгонять.

# Чек-лист перед ответом
1. JSON парсится: двойные кавычки, нет висячих запятых, \" и \n экранированы.
2. Имена в method2 и algo2 и code совпадают; нет дублей в functions.
3. Все next указывают на существующий no или "0". Нет бесконечных циклов и недостижимых шагов.
4. У каждого шага с predicate две строки и __rowspan на первой; у остальных __rowspan нет.
5. id и no без пропусков.
6. Типы, параметры, возвраты, формулы и формат вывода соответствуют заданию.
7. Все пункты «Алгоритма работы» выполнены в нужном порядке.
8. custom только по реально использованным конструкциям; classes заполнен для ООП.
9. Табуляции в коде, нет комментариев, файлы по папкам.
10. Опечатки в именах объектов (ct_obj вместо cl_obj) отсутствуют.

# Известные нюансы
- Эталоны пайплайном принимаются в обоих порядках (main первым/последним); для kind у методов класса принято "1", при "0" файл 1_2 тоже прошёл.
- Включать ли main в method2.main.functions: исходная инструкция говорит «кроме main», эталон 2_1 его включает. По умолчанию не включать; если пайплайн ругается, добавить.
- Пример вывода в тексте задания может быть неточным: ориентироваться на формат и формулу.
